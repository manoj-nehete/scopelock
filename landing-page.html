The Reality of Vibe Coding

Why AI-Assisted Projects Fail Without a Seatbelt

Prompting AI to write code feels effortless until subtle hallucinations, context limits, and silent regressions destroy your progress.

🎭

The "Yes Man" Agent

AI models enthusiastically report "I've implemented everything and it works perfectly!" when they haven't actually run tests or checked real outcomes.

🏃‍♂️

Premature Leaping

You ask for a simple login box, and the agent begins building billing systems or complex animations before your database or session logic even works.

💥

Silent Regressions

Your agent tweaks a button CSS style in Step 10 and accidentally wipes out security headers or database migrations written in Step 2.

🧠

Context Amnesia

Switching chat windows or bouncing between Claude, Codex, and Antigravity means the next agent starts blind, guessing what was already finished.

The ScopeLock Guarantee

Architected for Total Truth & Verification

A shared, local engine that keeps every coding agent disciplined, sequential, and accountable.

🛡️

Implementation ≠ Verification

An AI agent claiming a task is done only updates implementation status to implemented. It never marks it as verified until an actual test check passes or you attest to it.

🚦

Sequential Phase Gates

Phase 2 remains locked until all exit criteria and automated test runs for Phase 1 succeed. Coding agents cannot wander into future features until prerequisites pass.

🔍

Impact & Drift Detection

ScopeLock hashes workspace files. If an agent modifies a file without a requirement association, or modifies a file that broke previous tests, ScopeLock flags evidence as stale.

🤝

Universal Agent Handoff

Export a clean, Markdown handoff summary in one command. Start with Claude Code, switch to OpenAI Codex, and finish in Antigravity without losing a single requirement.

📊

Honest Visual Dashboard

Four independent summaries (Implementation, Verification, Blockers, Release Readiness). No misleading single "99% complete" percentage bar. Every count links to its exact record.

🔒

₹0 Cost & 100% Local

Runs entirely on your machine via Node.js. No subscriptions, no cloud databases, no external tokens, and no code ever leaves your laptop.

Deep Verification Features

Inspect the mechanics that make ScopeLock the gold standard for agentic software engineering.

Requirement Coverage Map

Directly links requirements to their associated implementation files, automated test commands, and execution evidence. Instantly see unverified code and gaps.

Feature A CLI: scopelock coverage REST /api/coverage
# Run coverage map $ scopelock coverage REQ-001: User Profile Creation Phase: P01 (Core Foundations) Files: src/user.ts, src/types.ts Checks: CHECK-001 (npm test user) Evidence: 1 run (passed, exit 0) Status: VERIFIED REQ-002: Password Validation Phase: P01 (Core Foundations) Files: src/auth.ts Checks: None Status: MISSING EVIDENCE

Dependency Flow & Cycle Detection

Visualizes requirement and phase prerequisites. Identifies exactly what tasks are eligible to begin right now, and rejects accidental cycle proposals before they corrupt state.

Feature B CLI: scopelock dependencies --list Screen-Reader Friendly
$ scopelock dependencies --list [ELIGIBLE TO START] • REQ-001: User Profile Creation (P01) • REQ-002: Password Validation (P01) [BLOCKED BY PREREQUISITES] • REQ-003: User Profile Page (P02) └── Awaiting: REQ-001, Phase P01 verification • REQ-004: Password Reset (P02) └── Awaiting: REQ-002

Change-Impact Tracking

Detects file changes affecting explicitly linked files using SHA-256 fingerprints. Automatically flags previously passed tests as stale so regressions never hide in plain sight.

Feature C Git & Non-Git Compatible Staleness Engine
$ scopelock impact [STALE EVIDENCE DETECTED] • File modified: src/auth.ts (SHA256 changed) └── Affected: REQ-002 (Password Validation) └── Evidence run RUN-003 invalidated └── Action: Re-run CHECK-002 to re-verify

Scope-Drift Review

Highlights newly created or unlinked files that agents modified without requirement association. Link them to existing tasks or document them as supporting infrastructure.

Feature G scopelock drift link scopelock drift supporting
$ scopelock drift [UNLINKED FILES (1)] • vite.config.ts (Created by agent) # Document it as supporting infrastructure: $ scopelock drift supporting vite.config.ts "Vite build configuration" ✓ Documented vite.config.ts as supporting file.

Milestone Checkpoints & Differential Progress

Take persistent named snapshots of project scope and execution status. Compare two checkpoints side-by-side to separate honest code progress from scope creep.

Feature F scopelock checkpoint create scopelock checkpoint compare
$ scopelock checkpoint compare CKPT-001 current SCOPE EVOLUTION: + 2 Requirements added (REQ-005, REQ-006) - 0 Requirements removed IMPLEMENTATION PROGRESS: • REQ-001: pending → implemented • REQ-002: pending → in_progress VERIFICATION DELTAS: • REQ-001: unverified → verified (CHECK-001)

Release-Readiness Auditor

Audits failed checks, stale evidence, active blockers, and unmet phase criteria. Generates a formal, actionable Markdown report before pushing to production.

Feature H scopelock readiness --export No Fake Green Lights
$ scopelock readiness --export release.md RELEASE READINESS AUDIT: NOT READY • Phase P01: PASSED (All criteria verified) • Phase P02: BLOCKED └── 1 Failed Check: CHECK-003 (exit 1) └── 1 Stale Evidence item └── 2 Unverified Exit Criteria ✓ Exported release readiness report to release.md

Requirements in Simple Markdown

No complex XML, no proprietary formats. Write your requirements in clean, readable Markdown that you and your AI agent both understand.

# Phase P01: Core Foundations - Constraint: Store all data locally on the user machine. ## REQ-001: User Profile Creation - Files: src/user.ts, src/types.ts - Acceptance (automated): User can be created with valid username and email. ## REQ-002: Password Validation - Files: src/auth.ts - Acceptance (automated): Passwords shorter than 8 characters are rejected. # Phase P02: User Experience - Phase depends: P01 ## REQ-003: Dark Mode Toggle - Depends: REQ-001 - Files: src/theme.ts - Acceptance (manual): User can toggle between dark and light themes smoothly.
Get Started in 3 Minutes

From 0 to 100 with ScopeLock

Follow this simple walkthrough to protect your project right now.

1

Install & Initialize

Clone the repository, build, and initialize ScopeLock in your project directory.

git clone https://github.com/manoj-nehete/scopelock.git && cd scopelock && npm ci && npm run build && npm link
2

Import & Lock Agreed Scope

Import your Markdown requirements and confirm the baseline scope revision.

scopelock init "My App" && scopelock import requirements.md && scopelock confirm
3

Connect Your Coding Agent

Configure local MCP automatically for your agent of choice.

scopelock connect claude-code # Or 'scopelock connect antigravity' or 'codex'
4

Launch the Visual Dashboard

Open the interactive graphical interface on localhost:4317 to inspect everything.

scopelock dashboard 4317
Common Questions

Frequently Asked Questions

Does ScopeLock require any paid APIs, tokens, or subscriptions?
No. ScopeLock is 100% free, open-source under the MIT license, and costs ₹0 in infrastructure. It runs entirely on your local machine using Node.js without any cloud database or AI API key required for the core engine.
Does any code or project data leave my local machine?
Never. ScopeLock stores all state in a simple local .scopelock/ directory in your project root. There are no tracking scripts, telemetry, or remote servers. Even command output logs automatically redact sensitive API keys and tokens before storing locally.
Can an AI agent run dangerous commands without my permission?
No. Coding agents cannot execute arbitrary command checks. All check definitions must be explicitly reviewed and approved by you (via scopelock check approve <ID>) before execution is permitted.
How does ScopeLock connect to Claude Code, Codex, or Antigravity?
ScopeLock features built-in adapters that write standard local configuration files (like .mcp.json, CLAUDE.md, AGENTS.md, or .agents/rules) connecting directly to the local ScopeLock Model Context Protocol (MCP) server.
What happens if my agent hallucinates or goes out of scope?
ScopeLock immediately catches it. If an agent tries to modify unapproved files, ScopeLock highlights it in the Scope Drift review. If it claims a requirement is complete, it stays strictly in implemented status until actual test evidence passes.
